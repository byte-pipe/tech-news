# Changing How We Develop Ladybird

Today, we are transforming the way developers contribute to the Ladybird project by introducing a new set of rules for code input and validation. As part of this change, our current acceptance policy on public pull requests will be adjusted to ensure that only experienced maintainers can introduce changes into the codebase.

**Background**

Ladybird's success has not been solely based on technical contributions from the outside community, but rather due to a combination of dedication, responsibility, and understanding among its contributors. In recent years, the open source landscape has seen numerous cases where patches became part of larger projects without proper vetting.

Meanwhile, AI tools have increasingly become integral in code development, changing the dynamics rapidly enough to undermine our initial assumption about who contributed to certain lines of work. As a result, maintaining consistency in evaluating contribution efforts is no longer as straightforward, and we need to establish stricter guidelines for contributors.

**Key Points**

*   The current policy will transition into a new role-based distribution system
*   Maintainer-led contributions are encouraged but not expected directly from users
*   External code can be reviewed under the terms of the license but in most cases it does not belong in Ladybird.
*   A single submitter is no longer necessary.
