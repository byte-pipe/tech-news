# On Rendering Diffs

## Problem with Large Diff Reviews
- Small/medium PRs are easy to navigate; large, autogenerated, or multi‑file changes become sluggish.
- Review tools often load one file at a time, require separate loading, or suffer from slow navigation.
- These limitations force reviewers to work around the tool, reducing productivity.

## Introducing Diffs and CodeView
- Six months ago the team released **Diffs**, a package aimed at making code and diff rendering reliable.
- Initial release included `File` and `FileDiff` components; performance feedback led to a simple virtualizer and worker‑thread syntax highlighting.
- Remaining issues (O(n×m) complexity, high memory, virtualization blanking) prompted the creation of a higher‑level component: **CodeView**.

## Goals of CodeView
- Render any diff reliably within browser limits (CPU, memory, physical constraints).
- Provide a virtualization‑first review surface that handles large diffs “nearly instantly.”
- Allow teams to focus on surrounding product features (workflows, automation, CI, collaboration) instead of building diff rendering from scratch.

## Core Challenges Addressed
- **Rendering:** DOM size grows quickly, causing scroll and interaction lag.
- **Processing:** Repeated per‑file operations become expensive at scale.
- **Memory:** Transforming large files into renderable structures can hit browser memory limits and trigger frequent garbage collection.

## Virtualization Strategy
- **Windowing:** Only render content near the viewport; as the user scrolls, new content is rendered and off‑screen content is removed.
- Benefits: lower memory usage, reduced layout/paint work, smaller DOM.
- Trade‑offs: virtualizer must estimate element heights and stay synchronized with scroll events; fast scrolls can expose blank regions if JavaScript lags.

### Common Virtualization Techniques
1. **Native Scroll Region**
   - Create a scrollable area with full estimated height; position visible items accordingly.
   - Keeps native scrollbar behavior and accessibility.
   - May lag behind visual scroll position on rapid jumps; larger buffers mitigate blanking but increase DOM load.
2. **Sticky/Fixed Container with `requestAnimationFrame`**
   - Render visible content in a fixed container and update via animation frames.
   - Eliminates blanking because the container does not move with the scroll.
   - Can cause hitching if JavaScript cannot keep up; limited to 60 Hz on some browsers (e.g., Safari).

## Demo and Availability
- **CodeView Playground:** Accessible at `DiffsHub.com` (replace `github` with `diffshub` in the URL) to view any public GitHub PR diff virtually instantly.
- **Package:** Latest version available on npm as `@pierre/diffs`; documentation and component source are publicly accessible.
