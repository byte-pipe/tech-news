## MCP 201 – Connecting Claude to the rest of your stack
1. **Key definitions**  
   - **MCP**: a bundle of actions a tool exposes so Claude can invoke them (e.g., send Slack message, pull data).  
   - **AI Harness**: the runtime layer (Claude Cowork, Claude Code, or Codex) that executes prompts and calls MCPs.  
   - The MCP describes *what* a tool can do; the harness performs the action.  

2. **Ways to connect tools**  
   - **MCPs** (standard, plug‑and‑play).  
   - **Direct prompts / API calls** for tools without an MCP or to extend MCP functionality.  
   - Claude Code is used as the default harness in the examples, but other harnesses work similarly.  

## Getting more out of your MCPs
- **Combine multiple MCPs** in a single Claude session to orchestrate cross‑tool workflows.  
- **Wrap MCP calls in reusable “skills”** so the same pattern runs automatically each time.  
- **Schedule workflows** (e.g., daily reports) so they execute without manual prompting.  
- Caution: too many active MCPs can slow response time; balance breadth and performance.  

## How MCPs address common LLM limitations
| Limitation | Why it matters | MCP‑based solution |
|------------|----------------|-------------------|
| Generic output (“slop”) | Claude lacks product‑specific context when only given a prompt. | Pull brand guidelines, positioning docs, or design specs from connected tools (Framer, Airtable, etc.) to provide concrete context. |
| Lack of up‑to‑date data | Prompt‑only approaches use stale or imagined information. | Query live data sources (CRM, databases, analytics) via MCPs to embed current facts. |
| Manual hand‑offs | Users must copy results between apps, increasing error risk. | End‑to‑end automation: Claude triggers actions (e.g., create Airtable record, launch Zapier workflow) directly from the same conversation. |
