# Why write code in 2026?

## Main argument
- Building a “software factory” means providing the infrastructure (prompts, knowledge bases, automated tests, linting, type systems, evaluations) that keeps AI agents productive and safe.  
- Even a low‑quality model, when constrained by this infrastructure, can produce acceptable changes, making the act of manually reading or writing code feel unnecessary.

## Why writing code still matters
- **Direct thinking**: Writing code lets me think directly in the execution environment rather than translating ideas through English.  
- **Attention & ownership**: Actively editing code forces deeper attention, creates a sense of ownership, and reveals fragility that passive review misses.  
- **Architectural insight**: Cleaning, documenting, and debugging code clarifies architectural principles and reduces hidden exceptions, which benefits both humans and agents.  
- **Precision**: Code provides a calibrated, executable specification that English cannot match for algorithmic work.  

## Risks of over‑reliance on agents
- Agents are not compilers; they behave more like newly hired interns who interpret partial, possibly sloppy code and imprecise change descriptions.  
- Without human‑crafted discipline, agents may amplify bad decisions (e.g., unnecessary indirection for a one‑off use of local storage).  
- Agents rarely follow “boy‑scout” practices—leaving code better than they found it—so they can increase technical debt if left unchecked.  

## Role of humans in the software factory
- Humans must still dive into low‑level details, refactor, and experiment to improve architecture and performance.  
- Hands‑on work lets us set patterns, evaluate metrics, and guard against the accumulation of slop that would later hinder agents.  
- The combination of human‑written code and AI‑driven automation yields a stronger, more maintainable system.
