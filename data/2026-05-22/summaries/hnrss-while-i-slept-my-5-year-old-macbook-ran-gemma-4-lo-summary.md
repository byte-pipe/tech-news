# While I slept, my 5‑year‑old MacBook ran Gemma 4 locally and indexed a year of video — SimbaStack

## Context and problem
- I split my year between three‑month stints in the Maasai Mara (shooting with iPhone, DJI Pocket, drone, Nikon Z8, Ray‑Ban Metas) and long days in front of a terminal working on software.
- The constant flow of raw footage creates an archive that grows faster than I can edit; most clips never get revisited.
- Existing SaaS AI‑video tools (Eddie AI, Higgsfield, Submagic, Buffer) were too expensive, required labeled footage, and risked brand damage for a travel business.

## Realisation
- The core issue is **indexing** an unlabeled archive so clips can be searched in natural language.
- DaVinci Resolve Studio already provides many needed features (IntelliSearch, Smart Bins, Voice‑to‑Subtitle), reducing reliance on external services.
- By combining Claude Code, Resolve’s MCP, and ElevenLabs for voiceovers, the monthly cost dropped from $140 to $22.

## Solution architecture
- Built a **local‑first, side‑car index** that lives next to each video file, ensuring portability and resilience.
- Chose three vision back‑ends: Claude (via Max CLI, zero marginal cost), Anthropic API (speed), and a local LM Studio model (Gemma 4 31B) for bulk processing.
- Designed an exhaustive schema captured in a single vision pass: rating, technical quality, lighting, time‑of‑day, color palette, audio quality, people count, keywords, faces, location, transcript, prose description.

### Per‑clip pipeline
1. `ffprobe` → metadata extraction.  
2. `exiftool` → GPS lat/long/altitude.  
3. Nominatim reverse‑geocode → human‑readable location.  
4. `ffmpeg` → extract five evenly‑spaced 1920 px frames.  
5. WhisperX → transcription with word‑level alignment & speaker diarization (97 languages).  
6. InsightFace → detect faces, store 512‑dim ArcFace embeddings in a SQLite DB.  
7. Vision model → ingest frames, transcript snippet, folder context; output YAML front‑matter + prose description.  
8. Write side‑car `.description.md` file beside the clip.

- Side‑cars contain YAML (lighting, time‑of‑day, palette, embeddings, GPS) and a natural‑language description, enabling English queries and downstream LLM hand‑off.
- Folder‑level `_INDEX.json` and `_INDEX.mdat` provide quick grep and aggregation.

## Implementation details
- Entire system is a Claude Code skill: ~1,400 lines of Python, largely generated by Claude; author contributed architecture, prompts, schema, and debugging.
- Indexing runs on a 2021 16‑inch MacBook Pro M1 Max with 64 GB RAM; the model (Gemma 4 31B Q4) occupies ~28 GB, pushing the machine beyond pure RAM capacity but still feasible locally.

## Outcomes and reflections
- Local, privacy‑preserving indexing solved the bottleneck that prevented any footage from being edited or published.
- The approach avoided costly SaaS subscriptions and mitigated brand risk from AI‑generated content.
- Demonstrated that a five‑year‑old high‑end laptop can host a 31‑billion‑parameter LLM for bulk video analysis when paired with an efficient pipeline.
