# Building Software Is Learning

## Main Idea
- Building new software is fundamentally a learning process; you cannot fully specify requirements before you start.

## Why Feedback Loops Often Fail
- Typical pattern: a feature request → developer builds → the result does not match the request or is disliked.
- This occurs because the exact shape of the feature is discovered only while building it.

## Good News: Reduce the Time to Feedback
- The most valuable thing you can do is shorten the interval between “let me try this” and the reality check that follows.
- Embrace rapid learning by seeking the quickest possible way to validate assumptions.

## Practical Tactics for Faster Learning
- **Prototype quickly** – build a rough version in about an hour and show it for immediate feedback.  
- **Write a short spec** – spend 30 minutes outlining the approach and get it reviewed.  
- **Ship incrementally** – break the work into daily pieces so each day provides real‑world feedback.  
- **Focus on unknowns** – reduce scope to the parts you are unsure about; skip what you already know.  
- **Create a demo video** – circulate a mock‑up to gather opinions before any code is written.  
- **Draft a news post** – capture the idea in a few paragraphs instead of building a week‑long prototype.  
- **Provide example code** – share a README‑style snippet to test the API design before an SDK is built.  
- Combine several of these approaches for larger features.

## Principles for Effective Feedback
- Ask constantly: “How can I get feedback on what I’m trying to build as soon as possible?”  
- Ensure feedback is meaningful, not just bug reports from an obviously broken MVP.  
- Remove obstacles that make it hard for reviewers to test your work.  
- Merge small changes frequently; a single commit gives clearer signals than a batch of dozens.  
- Match the feedback method to the question (design feedback vs. usability feedback).

## Action Items for the Team
- Reflect on the last time you received valuable feedback and how often it occurs.  
- Identify concrete ways to increase the speed and quality of feedback this week.  
- Prioritize shipping small, learnable pieces quickly rather than large, speculative builds.
