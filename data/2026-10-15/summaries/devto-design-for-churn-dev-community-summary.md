## The Dev Community's Guide to Churn in AI

The Dev Community has long understood that churn within AI code is not a bad thing. In fact, it can be seen as a positive force for innovation and improvement. A shift in perspective can help us approach code change with a more sustainable approach.

The Dev Community has always recognized that the cost of creating high-quality software is time. Churn indicates that code is being rewritten or modified frequently, which may not be desirable. However, this frequent change can actually help us identify weak points in our code.

### Codebases are Gardens Not Buildings

Currently, our understanding of software like "codebases are becoming like gardens" is flawed. Gardens need to endure and remain structurally sound, whereas codebases can be viewed as transient, changing plants.

The Dev Community acknowledges that the traditional notion of code excellence often focuses on longevity rather than quality. Our goal should be to identify what high-quality code looks like, rather than what makes for a well-written program.

### Characteristics of High-Quality Churn

Code that churns a lot is indeed disposable. However, this quality does not directly equate to sloppy code. Quality ensures that the code is:

- Well-tested at edges
- Able to adapt to new circumstances
- Able to function without being destroyed

However, our mental model of quality is still tangled up with the importance of longevity. This fixation might drive churn to occur, but it does so in a misguided assumption that newer, better code always means better overall performance.

### Identifying Where Churn Lands

Churn frequently occurs in files like `app/models/article.rb` and `forem(spam_handler)`. While we take comfort in having some code remain unaffected, such as the spam handler, it's essential to recognize that churn is an inherent aspect of coding.

### Designing for Churn

A viable solution could involve explicitly naming and highlighting code layers, such as the core auth, feed sorting, and cache pipelines. This would guide developers towards more sustainable and high-quality decision-making.

In conclusion, churn is an integral aspect of AI development, and we should understand its implications more clearly. By shifting our focus towards the importance of quality, we can design codebases that incorporate continuous, sustainable changes rather than dismissive, short-lived ones.
