# The minimum you need to know about GitHub Actions - DEV Community

## What is GitHub Actions?

GitHub Actions is a built-in automation feature on GitHub that allows users to automate repetitive tasks by writing workflows in YAML or JS. It's an alternative to using scripts on the command line.

## Real-World Example of GitHub Actions

### Example of Building and Deploying a Hugo Site with GitHub Actions

Here's an example of how to use GitHub Actions to build and deploy a static site generated by Hugo:

### Required Sections of a GitHub Actions Workflow File

* `on`: specifies the events that trigger the workflow
* `yml`: or `yaml`: defines the workflow file
* `on-and-job`: specifies a specific job to run the workflow on a specific trigger
* `main`: a branch that triggers the workflow
* `schedule`: executes a workflow on a cron schedule
* `workflow_dispatch`: allows the workflow to be triggered manually

### Triggered Events

* `push`: whenever someone pushes a commit to the repository's main branch
* `branches`: whenever the repository is cloned or pushed to
* `merge`: whenever the repository is committed
* `workflow_dispatch`: manual triggering of the workflow

### Example Workflow File

```yml
# main
name: Build and Deploy Hugo Site
on:
  push:
    branches:
      - main

# Scheduled to run daily at 1:26 UTC
on:
  schedule:
    - cron: '* 1:26 * * *'

# Manual trigger
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v2

      - name: Login to GitHub
        uses: actions/login@v1

      - name: Set environment variables
        shell: export HugoVersion=latest
        run: echo $HugoVersion

      - name: Run workflow
        uses: actions/workflow-action@v2
        with:
          configFile: 'github/workflows/main.yml'
```

### Explanation of the Workflow File

* The `on` section defines the events that trigger the workflow:
	+ `push`: whenever someone pushes to the main branch
	+ `branches`: whenever the repository is cloned or pushed to
	+ `merge`: whenever the repository is committed
* The `on` section defines the scheduled trigger:
	+ `schedule`: executes a new job every day at 1:26 UTC
* The `job` section defines the workflow that will run on that trigger:
	+ `build-and-deploy`: a job that runs on an `ubuntu-latest` environment
	+ Steps that run during the workflow:
		- `Checkout repository`: clones the repository
		- `Login to GitHub`: logs in to GitHub using an action
		- `Set environment variables`: sets environment variables
		- `Run workflow`: executes the GitHub Actions workflow
* The `with` section passes the `configFile` parameter to the GitHub Actions workflow

This workflow is designed to build and deploy a Hugo site whenever someone pushes to the main branch or clones the repository and pushes to it. The `schedule` trigger executes the workflow every day at 1:26 UTC. The `workflow_dispatch` trigger allows the workflow to be manually triggered from the Actions tab.
